PROJECT CONCEPT:

RoundNest is a micro-investment simulation application that helps users build investment savings automatically through either transaction round-ups or scheduled auto-saving.

This is a SIMULATION only.
No real money, bank accounts, payments, financial transactions, or actual investments are performed.

CORE USER FLOW:

1. User opens RoundNest.
2. User chooses how they want to save:
   A. Round-Up Saving
   B. Auto-Save

ROUND-UP SAVING:

The user chooses a round-up target:
- ₹5
- ₹10
- ₹15
- ₹20

When a user enters a transaction amount, calculate the amount needed to reach the next multiple of the selected target.

Examples:
If target is ₹10:
₹237 → ₹240 → ₹3 saved
₹452 → ₹460 → ₹8 saved
₹101 → ₹110 → ₹9 saved

The round-up amount should be calculated dynamically.

AUTO-SAVE:

The user can choose:
- Weekly
- Monthly

And an amount such as:
- ₹100
- ₹200
- ₹500
- Custom amount

This should be represented as a scheduled savings simulation. Do NOT actually connect to a bank or deduct real money.

INVESTMENT THRESHOLD:

The application should track accumulated savings.

When savings are below ₹100:
Show progress toward the first simulated investment.

Example:

₹73 saved
₹27 more until your first investment

Show a progress bar.

When savings reach ₹100 or more:
Show an "Investment Unlocked" state.

The user can then choose between:

1. Simulated Digital Gold
2. Simulated Mutual Fund

Clearly label both as simulations.

INVESTMENT SIMULATION:

After the user selects an investment type, let them choose a time horizon:

- 1 month
- 3 months
- 6 months
- 1 year

Show an illustrative projected value and a simple animated/chart visualization.

IMPORTANT:
Do not claim that returns are guaranteed.
Use clearly labeled "Illustrative Projection" or "Simulated Value."

Include a small disclaimer:

"Simulation only. Projected returns are illustrative and are not guaranteed. This application does not provide financial advice."

The simulated return assumptions should be configurable in the backend rather than hardcoded throughout the frontend.
